# 📚 유아교육·그림책 도메인 RAG 파이프라인 설계 및 기술 문서

## 1. 프로젝트 개요
- **목표:** 유아교육 현장(누리과정)과 그림책 데이터를 연계하여 교사들의 수업 준비, 월별 놀이 계획, 맞춤형 발문(질문) 구성을 지원하는 AI RAG(Retrieval-Augmented Generation) 서비스.
- **핵심 기능:**
  - 누리과정 원문 및 도서관 정보나루 API 도서 데이터 연계 벡터 검색
  - LangGraph 기반의 멀티 스텝(검색어 추출, 누락 방지, 답변 생성) 파이프라인 구성
  - 교사 지원 도구(연령별 그림책 추천, 누리과정 연계 포인트 및 수업 활동 발문 제안)

## 2. 데이터 수집, 정제(쓰레기 처리) 및 벡터 DB 구조
### 2.1 문서 수집 및 쓰레기(Noise) 데이터 처리
- **수집 소스:**
  - 교육부·보건복지부 고시 [2019 개정 누리과정] 원문 JSON (`nuri_curriculum.json`)
  - 도서관 정보나루(library.kr) 오픈 API 도서 대출 및 메타데이터
  - 수집된 원문 내 불필요한 HTML 태그, 특수문자, 연속된 공백 및 개행 문자를 정규식(`re.sub`)을 통해 정제.
  - API 응답 중 필수 메타데이터(도서명, 저자, ISBN 등)가 누락되었거나 빈 값(`None`, `""`)인 데이터는 색인 단계에서 제외하여 검색 정확도 저하 방지.

### 2.2 두 개의 벡터 DB (컬렉션) 구조 및 데이터 필드
Chroma DB 내에서 도메인 특성에 맞추어 **누리과정 컬렉션**과 **도서 정보 컬렉션**의 2개 스토어로 분리하여 관리합니다.

| 구분 | 컬렉션 명 | 주요 데이터 필드 (Metadata & Document) |
| :--- | :--- | :--- |
| **1. 누리과정 DB** | `nuri_collection` | • **Document:** 청크 텍스트 (영역 및 내용범주 헤더 결합)<br>• **Metadata:** `domain` (영역), `category` (내용범주), `content_id` (고유 ID), `age_group` (연령) |
| **2. 도서 정보 DB** | `book_collection` | • **Document:** 도서 소개 및 요약 텍스트<br>• **Metadata:** `book_name` (도서명), `author` (저자), `isbn` (ISBN), `nuri_link` (연계 누리과정 영역) |

- **고정 ID 및 멱등성 보장:** `content_id#n` 형태의 고정 문자열 ID를 부여하고 `upsert` 방식을 적용하여, 파이프라인을 여러 번 재실행해도 중복 데이터가 생성되지 않고 처리 속도가 최적화되도록 설계.

## 3. 청크 분할 전략 및 파라미터 선정 근거
- **분할 알고리즘:** `RecursiveCharacterTextSplitter` 활용
- **설정값 및 정의 이유:**
  - **`CHUNK_SIZE = 300`:** 유아교육 누리과정의 문장 단위 및 내용 범주별 세부 설명이 하나의 문맥으로 온전히 유지되기에 가장 적절한 토큰/글자 수 크기. 너무 크면 무관한 정보가 섞이고, 너무 작으면 문맥이 끊기는 문제를 방지함.
  - **`CHUNK_OVERLAP = 50`:** 청크 경계에서 문장이나 핵심 키워드가 유실되는 것을 막고, 앞뒤 문맥의 연속성을 확보하기 위한 오버랩 길이.
  - **검색 개수(`TOP_K`):** 최종 프롬프트의 토큰 제한 준수 및 노이즈 문서 유입 최소화를 고려하여 상위 3~5개의 관련 청크만 선별하도록 설정.

## 4. LangGraph 파이프라인 및 3단계 아키텍처
LangGraph를 도입하여 정형화된 순서에 따라 RAG의 품질을 높입니다.
  ### 4.1 세부 단계별 역할 및 출력 형식
  1. **검색어 추출 (Query Expansion/Rewrite):**
    - **역할:** 사용자의 일상적인 질문(예: "아이들이랑 동물놀이 하고 싶어요")을 벡터 검색에 최적화된 키워드 및 누리과정 용어(예: "신체운동·건강 > 신체활동")로 확장·변환.
    - **출력 형식:** 재작성된 검색 쿼리 문자열 및 추출된 키워드 딕셔너리 형태의 State 데이터.
  2. **정보 누락 방지 및 필터링 (Relevance Check):**
    - **역할:** 검색된 문서가 사용자의 의도에 부합하는지 검증하고, 유아 연령 및 누리과정 영역 조건이 누락되지 않았는지 선별.
    - **출력 형식:** 유효성 검증 여부(`is_valid: bool`)와 필터링된 청크 리스트.
  3. **답변 생성 (Generate):**
    - **역할:** 검증된 근거 문서들을 바탕으로 교사 맞춤형 수업 계획 및 발문 제안을 생성. 환각 현상 방지를 위해 문서에 없는 내용은 "확인되지 않습니다"로 응답하도록 제어.
    - **출력 형식:** 마크다운 기반의 구조화된 교육 계획 텍스트 및 인용 번호(`[근거 N]`).

  ---

## 5. UI 표시 방식 및 쿠키 설계 이유
- **답변 표시 방식 (UI/UX):**
  - 사실 정보(누리과정 연계, 도서 정보 등)에는 명확한 출처 인용 번호(`[근거 N]`)를 표기.
  - 활동 및 발문 예시는 교사 지원용 제안형 콘텐츠이므로 유연한 가독성을 제공하기 위해 아코디언 및 카드 UI 형태로 분리하여 렌더링.
- **쿠키 기능 설계 이유:**
  - 교사 사용자의 최근 검색 기록 유지, 맞춤형 유아 연령대(예: 만 3세반, 만 4세반) 세션 유지, 그리고 자주 찾는 누리과정 영역 설정을 저장함으로써 매번 검색 조건을 재입력해야 하는 번거로움을 줄이고 사용자 경험(UX)을 극대화하기 위해 도입.

## 6. 클라이언트, 청킹 및 콘솔 트러블슈팅 (문제 및 처리 과정)
- **클라이언트 연동 문제 (CORS 및 비동기 통신):**
  - *문제:* Django 백엔드와 프론트엔드 간 API 통신 시 CORS 에러 발생.
  - *해결:* `django-cors-headers` 미들웨어를 설치하고 `CORS_ALLOWED_ORIGINS` 설정을 추가하여 정상적인 비동기 데이터 통신 보장.
- **청킹 및 인코딩 문제:**
  - *문제:* JSON 파일 로드 시 특수문자 및 한글 깨짐 현상 발생.
  - *해결:* 파일 읽기/쓰기 시 `encoding='utf-8'` 명시 및 `RecursiveCharacterTextSplitter` 파라미터 최적화를 통해 텍스트 유실 방지.
- **콘솔(Terminal) 에러 및 처리:**
  - *문제:* Chroma DB 초기 색인 중 API 호출 횟수 초과(Rate Limit) 또는 환경 변수(`.env`) 누락으로 인한 에러 발생.
  - *해결:* `.env.example` 파일을 기반으로 `OPENAI_API_KEY` 설정을 검증하는 예외 처리 구문을 추가하고, 멱등성(`upsert`) 적용으로 재실행 시 서버 부하 최소화.
